[OpenFeature](https://openfeature.dev) is a [CNCF-incubating](https://www.cncf.io/projects/openfeature/) open standard for feature flagging. GrowthBook provides OpenFeature provider SDKs for **JavaScript** (Node.js and web), **Python**, **Go**, **.NET**, **Java**, **Swift** (iOS and other Apple platforms), and **Kotlin** (Android and the JVM), listed in the [OpenFeature ecosystem](https://openfeature.dev/ecosystem/?instant_search%5Bquery%5D=growthbook).

## Prerequisites

- A GrowthBook account ([cloud](https://app.growthbook.io) or [self-hosted](/self-host))
- An **SDK Connection** key — create one under **Settings → SDK Connections** in the GrowthBook UI
- The API host:
  - Cloud: `https://cdn.growthbook.io`
  - Self-hosted: your own GrowthBook URL (e.g. `https://growthbook.example.com`)

## Why Use OpenFeature with GrowthBook?

OpenFeature defines a vendor-neutral interface for evaluating feature flags. Using a GrowthBook OpenFeature provider means:

- **Vendor portability** — Your flag evaluation code is identical regardless of which provider is active. Switching from or to GrowthBook only requires changing the provider bootstrap, not a single flag call.
- **Standardized API** — Teams use the same OpenFeature interface they already know across all services.
- **Ecosystem compatibility** — OpenFeature-aware tooling — including [OpenTelemetry hooks](https://openfeature.dev/docs/reference/technologies/observability/opentelemetry) and other instrumentation — works automatically with GrowthBook.
- **Polyglot consistency** — The same conceptual API spans JavaScript, Python, Go, .NET, Java, Swift, Kotlin (and more), giving teams a single mental model.

<Tip>
**When to use the native GrowthBook SDK instead**

The native GrowthBook SDKs expose features that go beyond the OpenFeature interface: Sticky Bucketing, AI Visual Editor experiments, and inline experiment definitions. If you need those capabilities, use the [native SDK](/lib) for your language instead.

</Tip>

## Installation & Setup

<Tabs>
<Tab title="JavaScript">

Use `@openfeature/growthbook-provider` with `@openfeature/server-sdk` in Node.js. Use `@openfeature/growthbook-client-provider` with `@openfeature/web-sdk` in the browser. The two providers are not interchangeable — either one throws if you register it with the wrong SDK.

<Warning>
Unlike the Python, .NET, and Java providers, the JavaScript providers pass the evaluation context to GrowthBook unchanged. `targetingKey` is **not** mapped to GrowthBook's `id` attribute, so you must set `id` yourself — see [Evaluation Context](#evaluation-context-targeting-attributes).
</Warning>

Both packages are published from [open-feature/js-sdk-contrib](https://github.com/open-feature/js-sdk-contrib) and are currently pre-1.0. Report issues there rather than on the GrowthBook repos.

<Tab title="Node.js (server)">

**GitHub:** [js-sdk-contrib/providers/growthbook](https://github.com/open-feature/js-sdk-contrib/tree/main/libs/providers/growthbook) &nbsp;|&nbsp; **npm:** [@openfeature/growthbook-provider](https://www.npmjs.com/package/@openfeature/growthbook-provider)


```js
import { OpenFeature } from "@openfeature/server-sdk";
import { GrowthbookProvider } from "@openfeature/growthbook-provider";

const gbClientOptions = {
  apiHost: "https://cdn.growthbook.io",
  clientKey: "sdk-abc123",
  // Only required if you have feature encryption enabled
  // decryptionKey: "key_abc123",
};

// The second argument is optional. `timeout` bounds how long startup can block
// on the initial feature fetch; streaming is already enabled by default.
await OpenFeature.setProviderAndWait(
  new GrowthbookProvider(gbClientOptions, { timeout: 2000 }),
  { region: "us-east" }, // optional global attributes, applied to every evaluation
);

const client = OpenFeature.getClient("my-app");
```

The provider reads global attributes once, when it initializes. Pass them as the second argument to `setProviderAndWait` as shown above — calling `OpenFeature.setContext()` later does not update them on the server SDK.

## Evaluation Context (Targeting Attributes)

Pass user attributes to the OpenFeature client via an `EvaluationContext`. These become GrowthBook targeting attributes used for percentage rollouts, feature targeting rules, and experiment bucketing.

GrowthBook buckets users on the `id` attribute by default. The Python, .NET, Java, Swift, and Kotlin providers map the OpenFeature `targetingKey` to `id` for you. In Swift and Kotlin, when the context has both, `identityPrecedence` decides which wins (`targetingKey` by default). The **JavaScript and Go providers do not** — they pass the context through unchanged, so you must set `id` yourself.

<Warning>
If `id` is missing, GrowthBook has nothing to hash on: percentage rollouts return their default value and experiments never assign a variation. Nothing raises an error, so the flag simply appears to be off. Set `targetingKey` and `id` to the same value — `id` does the bucketing today, and the pair keeps your code portable to providers that read `targetingKey`.
</Warning>

Additional attributes (e.g. `country`, `plan`, `email`) are matched against your feature flag targeting conditions.

The JavaScript examples use the Node.js server SDK, which accepts an invocation-level context. On the web SDK, call `await OpenFeature.setContext(context)` instead of passing context into each evaluation. The Swift and Kotlin SDKs also use a single global context: set it with `setEvaluationContextAndWait`, and each change replaces all attributes.

<CodeGroup>

```js JavaScript
const context = {
  // The JS providers do not map targetingKey — GrowthBook buckets on `id`.
  targetingKey: "user-123",
  id: "user-123",
  country: "US",
  plan: "premium",
  email: "user@example.com",
};
```

```python Python
from openfeature.evaluation_context import EvaluationContext

context = EvaluationContext(
    targeting_key="user-123",
    attributes={
        "country": "US",
        "plan": "premium",
        "email": "user@example.com",
    }
)
```

```go Go
evalCtx := openfeature.NewEvaluationContext("user-123", map[string]interface{}{
    // The Go provider does not map targetingKey — GrowthBook buckets on `id`.
    "id":      "user-123",
    "country": "US",
    "plan":    "premium",
    "email":   "user@example.com",
})
```

```csharp .NET
var context = new EvaluationContext(
    targetingKey: "user-123",
    new Dictionary<string, Value>
    {
        { "country", new Value("US") },
        { "plan",    new Value("premium") },
        { "email",   new Value("user@example.com") },
    }
);
```

```java Java
import dev.openfeature.sdk.EvaluationContext;
import dev.openfeature.sdk.MutableContext;

MutableContext context = new MutableContext("user-123");
context.add("country", "US");
context.add("plan", "premium");
context.add("email", "user@example.com");
```

```swift Swift
await OpenFeatureAPI.shared.setEvaluationContextAndWait(
    evaluationContext: ImmutableContext(
        targetingKey: "user-123",
        structure: ImmutableStructure(attributes: [
            "country": .string("US"),
            "plan": .string("premium"),
            "email": .string("user@example.com"),
        ])
    )
)
```

```kotlin Kotlin

import dev.openfeature.kotlin.sdk.OpenFeatureAPI
import dev.openfeature.kotlin.sdk.Value

OpenFeatureAPI.setEvaluationContextAndWait(

        targetingKey = "user-123",

            "plan" to Value.String("premium"),
            "email" to Value.String("user@example.com"),
        ),
    ),

```

## Evaluating Feature Flags

OpenFeature defines five value types. GrowthBook's feature flags map to all of them.

The JavaScript examples below use the Node.js server SDK, where evaluations are asynchronous and take an invocation-level context. On the web SDK the same calls are **synchronous and take no context argument** — they read the global context set via `await OpenFeature.setContext(...)`:

```js
// Web SDK equivalent
const enabled = client.getBooleanValue("dark-mode", false);
```

The Swift and Kotlin SDKs work the same way: evaluations are synchronous and read the global context.

<Note>
The JavaScript providers return GrowthBook's own `source` string as the evaluation `reason` (e.g. `experiment`, `force`, `defaultValue`) rather than the standard OpenFeature reasons such as `TARGETING_MATCH` or `STATIC`. The Swift and Kotlin providers return the standard reasons. Code that branches on `details.reason` is not portable across providers.
</Note>

### Boolean

The most common type — use for on/off feature gates.

<CodeGroup>

```js JavaScript
// Server SDK (async)
const enabled = await client.getBooleanValue("dark-mode", false, context);

// Returns full evaluation details (value, reason, variant, error)
const details = await client.getBooleanDetails("dark-mode", false, context);
```

```python Python
# Synchronous
enabled = client.get_boolean_value("dark-mode", False, context)

# Async (returns FlagEvaluationDetails with value, reason, variant, etc.)
details = await provider.resolve_boolean_details_async("dark-mode", False, context)
enabled = details.value
```

```go Go
// Returns the value with a default fallback
enabled, err := client.BooleanValue(context.Background(), "dark-mode", false, evalCtx)

// Returns full evaluation details (value, reason, variant, error)
details, err := client.BooleanValueDetails(context.Background(), "dark-mode", false, evalCtx)
enabled := details.Value
```

```csharp .NET
bool enabled = await client.GetBooleanValue("dark-mode", false, context);
```

```java Java
boolean enabled = client.getBooleanValue("dark-mode", false, context);
```

```swift Swift
let enabled = client.getBooleanValue(key: "dark-mode", defaultValue: false)

// Returns full evaluation details (value, reason, variant, error)
let details = client.getBooleanDetails(key: "dark-mode", defaultValue: false)
```

```kotlin Kotlin
val enabled = client.getBooleanValue("dark-mode", false)

// Returns full evaluation details (value, reason, variant, error)
val details = client.getBooleanDetails("dark-mode", false)
```

</CodeGroup>

## Configuration Options

| Option                     | JavaScript | Python | Go  | .NET | Java | Swift | Kotlin | Description                                       |
| -------------------------- | :--------: | :----: | :-: | :--: | :--: | :---: | :----: | ------------------------------------------------- |
| `api_host` / `apiHost`     |     ✓      |   ✓    |  ✓  |  ✓   |  ✓   |   ✓   |   ✓    | GrowthBook CDN or self-hosted URL                 |
| `client_key` / `clientKey` |     ✓      |   ✓    |  ✓  |  ✓   |  ✓   |   ✓   |   ✓    | SDK Connection key from GrowthBook                |
| `decryption_key`           |     ✓      |   ✓    |  —  |  —   |  —   |   ✓   |   ✓    | Key for encrypted SDK endpoint payloads           |
| `cache_ttl`                |    ✓\*     |   ✓    |  ✓  |  —   |  —   |   ✓   | ✓\*\*  | Seconds before re-fetching features (default: 60) |
| `enabled`                  |     ✓      |   ✓    |  —  |  ✓   |  —   |   ✓   | ✓\*\*  | Enable/disable the provider entirely              |
| `qa_mode`                  |     ✓      |   ✓    |  —  |  —   |  —   |   ✓   | ✓\*\*  | Forces all experiments into the control variation |

\* In JavaScript, `cache_ttl` lives on the provider's optional second argument as `{ cacheSettings: { staleTTL: 60000 } }` rather than in the client options object. Every other JavaScript option in this table goes in the client options object.

In Swift, `cache_ttl` is the provider's `ttlSeconds` argument and the other options are `GrowthBookModel` fields (`encryptionKey`, `isEnabled`, `isQaMode`).

\*\* In Kotlin, set these through the provider's `configureSdk` argument, which receives the GrowthBook SDK builder: `setCacheMaxAge(ms)`, `setEnabled(...)` and `setQAMode(...)`. Pass `encryptionKey` to the provider directly.

## Shutdown & Cleanup

Always shut down the provider when your application exits to close background connections.

<CodeGroup>

```js JavaScript
await OpenFeature.close();
```

```python Python
await provider.close()       # async
# or
provider.close_sync()        # sync
```

```go Go

```

```csharp .NET
provider.Dispose();
```

```java Java
provider.shutdown();
```

```swift Swift
// OpenFeature Swift doesn't shut providers down, so close the provider yourself
provider.close()
```

```kotlin Kotlin
OpenFeatureAPI.shutdown() // from a coroutine
```
